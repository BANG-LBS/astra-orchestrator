# 个人真实案例测试

本文区分 V2 的最新个人案例和 V1 的历史观察。业务内容已脱敏，原始数据、完整报告及运行日志不随仓库公开。

## V2：同一简短需求下的实际表现

2026年9月，用同一原始表格和简短业务提示，分析某产品近30天转化表现靠前的30篇小红书笔记。先执行基准组，再执行工具组；两组根模型均为 GPT-6 Astra `xhigh`。

- **基准组（原生Astra）**：未启用编排 Skill。只给予两组共有的必要子代理授权，没有选模、交付或额度停止线建议。
- **工具组（Astra智能编排开启）**：相同业务提示，仅额外显式调用 `astra-orchestrator`。
- 两组各运行一次。因额度用尽而中断时，自然重置后仅发送最短继续请求；先完成基准组及其子任务，再启动工具组。
- 目标是观察清晰、简单的目的提示能否得到有用的交付，以及实际成本和使用体验，而非证明所有任务的通用节省率。

### 交付与实际使用

| 观察项 | 基准组 | 工具组 |
| --- | --- | --- |
| 根模型 | GPT-6 Astra xhigh | GPT-6 Astra xhigh |
| 子模型 | 两个 Astra xhigh 子任务 | Luna max 与 Sol xhigh |
| 交付 | 完整报告、逐篇分析与可追溯依据 | 完整报告、逐篇分析与可追溯依据 |
| 来源复核 | 匹配原表与历史内容、图片和可用字幕 | 同样复用历史素材，另核验30篇当前公开页 |
| 报告交互 | 关键词搜索 | 关键词、图文/视频和写法类别组合筛选 |
| 用户阅读反馈 | 表达更偏专业分析，部分内容需要进一步理解 | 更易理解，逐篇分析更方便查找和复用 |
| 追加业务要求 | 0次 | 0次 |

工具组实际请求了30篇当前公开页面，并记录标题、附文与图片标识的比较结果，发现一篇附文发生变化。它利用历史存档中的分享链接和素材，并非从零重新采集全部图文视频。两组都未完整观看所有视频，不把封面和部分可用字幕描述为完整视频覆盖。

本例中，工具组增加了有用的来源核验和交互功能。用户的阅读反馈支持其在这项业务中的易读性与使用便利性优势；“读起来更专业”并不直接证明分析更准确，两组无需补充业务提示也不等于已开展新手用户研究。

### Token 与 API 等价成本

按去重后的单次模型响应统计所有根及子任务，包含失败片段和额度恢复段，排除监测对话。

| 组别与模型 | 输入 token | 其中缓存输入 | 输出 token | API 等价成本（美元） |
| --- | ---: | ---: | ---: | ---: |
| 基准组根任务：Astra | 5,381,883 | 5,092,864 | 23,658 | 9.165954 |
| 基准组子任务1：Astra | 498,504 | 442,368 | 4,806 | 1.244028 |
| 基准组子任务2：Astra | 325,705 | 304,000 | 8,369 | 0.939500 |
| 工具组根任务：Astra | 4,528,657 | 4,217,600 | 27,068 | 8.681570 |
| 工具组子任务：Luna | 1,548,942 | 1,459,200 | 32,865 | 0.039999 |
| 工具组子任务：Sol | 1,466,951 | 1,400,192 | 19,570 | 0.609256 |

| 汇总 | 基准组 | 工具组 |
| --- | ---: | ---: |
| 总 token（输入＋输出） | 6,242,925 | 7,624,053 |
| API 等价成本 | 11.349482美元 | 9.330825美元 |

工具组总 token **多22.1%**，API 等价成本却**低约17.8%**，约少2.02美元。原因是模型分工不同，token 的单价不同；不能只把不同模型的 token 相加来判断经济性。

计价使用2026年9月27日核实的 [OpenAI Standard API 单价](https://developers.openai.com/api/docs/pricing)，单位为美元/百万 token：

| 模型 | 非缓存输入 | 缓存输入 | 输出 |
| --- | ---: | ---: | ---: |
| GPT-6 Astra | 10 | 1 | 50 |
| GPT-6 Sol | 2 | 0.20 | 10 |
| GPT-6 Luna | 0.10 | 0.01 | 0.50 |

每个模型分别计算：

```text
等价成本 = [(输入 − 缓存输入) × 输入单价
          + 缓存输入 × 缓存单价
          + 输出 × 输出单价] ÷ 1,000,000
```

缓存输入已包含在输入内，推理输出已包含在输出内，不重复计费。本次记录没有缓存写入 token，单次输入未达到长上下文加价门槛。上述为按统一 Standard 口径重算的 token 等价成本，不是实际 API 账单、订阅扣款或五小时额度换算；不含工具服务费、税费或其他附加费。

### 解释结果时保留的边界

- **两组都利用历史素材。** 基准组省去了重新请求当前页面的工作，工具组也受益于现成链接、图片和字幕。无法用这次记录计算两组完全从零执行的成本。
- **实际交付范围不同。** 工具组多做当前页面复核和组合筛选；这些成本已包含在9.33美元中，不再额外虚构一个节省金额。
- **额度起点与中断位置不同。** 基准组起始余量较少，两个子任务因额度限制结束，由根任务恢复后完成交付；工具组的两个子任务完成，根任务在收尾时中断。因此不能把全部差额单独归因于 Skill。
- **监测开销不一致。** 基准组运行期间监测更频繁，已与被测任务 token 成本分开。账户额度读数存在延迟并混有监测消耗，本例不公布一个确定的五小时额度节省率。
- **各一次、固定顺序、非盲评。** 用户阅读体验来自本次实际使用，不推广成所有用户与业务的结果。为保护业务隐私，不公开逐条原始日志，因此外部读者可以复核上表算术，但不能独立重放整个任务。
- **后续门控澄清另行记录。** 当前版本补清了交付后修改继续生效、启用安静和退出说明的规则；本次任务成本记录不构成这些后续修改的独立行为验证。

本例支持把 V2 用于实际业务：核心交付完整，工具组提供了额外有用工作和更方便使用的报告，API 等价成本仍更低。后续根据真实业务需求与反馈改进，不再为寻找一个普遍结论追加验证实验。

## V1：历史背景，单独保留

以下三组发生在 GPT-6 Luna／Sol 路由更新之前，完成范围和提示方式不相同，不与上述 V2 数字合并：

| 组别 | 提示方式 | 当时观察的五小时额度变化 | 完成范围 |
| --- | --- | ---: | --- |
| 基准组（原生Astra） | 简短需求 | 约24个百分点 | 主要依赖标题、表格和经营数据；正文访问受阻后缩小范围 |
| 工具组（Astra智能编排开启） | 同类简短需求 | 约69个百分点 | 阅读相关内容、检查样本范围，形成逐篇映射和完整报告 |
| 人工深度组（原生Astra+深度提示词） | 明确全文读取、范围校验和完整交付 | 两段合计约77个百分点 | 自然额度中断后继续，完成更广泛的内容检查 |

人工深度组当时预留74%的窗口余量，耗尽后恢复并继续消耗约3个百分点。以上是历史观测，不是同工作量、无中断的独立账单；本次没有对其旧日志作同口径重算。

这些观察促成了当前设计：将委派判断、上下文控制和验收流程收进 Skill，减少用户手工编写过程要求的负担。它们不证明固定节省率或任何任务上的必然质量优势。
